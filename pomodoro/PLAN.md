# 포모도로 웹서비스 — V1 설계

## 제품의 중심
프로젝트와 할 일을 고른다 → 집중 세션을 실행한다 → 결과를 짧게 돌아본다 → 일·주·월 기록과 주간 회고에서 자신의 시간을 확인한다.

V1에는 회원가입/로그인, 커스텀 집중·짧은 휴식·긴 휴식, 프로젝트/할 일, 예상 대비 실제 세션, 짧은 회고, 통계, Weekly Review, 알림, JSON 내보내기와 데이터 삭제를 포함한다. 게임 보상은 V1에 섞지 않는다.

## 화면 흐름
회원가입 또는 로그인 → 집중 화면 → 프로젝트와 할 일 생성 → 할 일 선택 → 타이머 시작 → 일시정지/재개 또는 중단 → 완료 시 회고 → 휴식 → 다음 집중.

항상 접근 가능한 보조 화면: 할 일, 기록·통계, 주간 회고, 설정·데이터, 사용 가이드.

## 데이터의 의미
- Project: 같은 목표로 묶인 일. 예: 운영체제 공부.
- Task: 실행 가능한 작은 일. 예: 스케줄링 문제 5개 풀기. 예상 Pomodoro 수를 저장한다.
- Focus Session: 한 번 실행한 타이머. 시작 당시 목표 시간을 별도로 보관한다. 나중에 설정을 바꿔도 과거 기록이 변하지 않는다.
- 실제 Pomodoro: 끝까지 완료한 집중 세션 수. 중단 세션은 집중 시간에 포함하지만 완료 횟수에는 포함하지 않는다.
- Review: 완료 또는 중단 세션의 집중도(1~5), 방해 요소, 한 줄 메모. 입력은 선택 사항이다.
- Weekly Review: 월요일부터 일요일까지의 주간 기록을 보고 성과/어려움/다음 주 계획을 직접 적는다.
- 통계 날짜: V1은 Asia/Seoul을 기준으로 세션이 끝난 날짜에 시간을 합산한다. 자정을 넘은 세션을 날짜별로 분할하지 않는다.

## 타이머 규칙
서버에 실행 상태를 저장한다. 브라우저는 초를 단순히 1씩 줄이는 대신 서버의 시작 시각과 누적 실행 시간을 바탕으로 남은 시간을 표시한다. 새로고침 후에도 상태를 복원한다. 사용자당 진행 중인 집중/휴식은 하나만 허용한다. 완료 요청이 중복되어도 기록을 중복 생성하지 않는다. 잠든 컴퓨터를 깨운 경우 경과 시간을 반영하되 알림은 브라우저가 다시 실행될 때 전달될 수 있다.

집중 완료 후 짧은 휴식을 제안하고, 설정한 집중 횟수마다 긴 휴식을 제안한다. 다음 세션은 사용자가 시작한다. 휴식은 집중 통계에 포함하지 않는다.

## 개발 순서와 완료 조건
1. DB와 인증: 회원가입·로그인·로그아웃, 비밀번호 해시, 사용자별 데이터 격리.
2. 프로젝트/할 일: 생성·수정·삭제, 예상 횟수, 완료 상태.
3. 타이머: 시작·일시정지·재개·중단·완료, 새로고침 복원, 중복 완료 방지.
4. 회고: 집중도·방해 요소·메모, 기록 수정·삭제.
5. 통계: 날짜/주/월 선택, 프로젝트별 집계, 예상/실제 비교, 주간 회고 저장.
6. 설정/데이터: 집중 및 휴식 길이, 알림 권한, 내보내기, 데이터/계정 삭제.
7. 검증: 다른 사용자 접근 차단, 잘못된 입력, 중복 시작/완료, 일시정지 시간 제외, 통계 정확성.

## 단계적 확장
- V1.1: 이메일 확인·비밀번호 재설정, 실제 운영 환경의 HTTPS·로그·백업·복원.
- V2: EXP/Coin/Level과 업적. 완료 이벤트를 기준으로 보상을 지급하고, 세션 ID별 유일한 보상 원장을 두어 중복 지급을 막는다.
- V3: Daily/Weekly Quest. 규칙 버전과 기간 경계를 저장하고, 쉬는 날을 실패로 처벌하지 않는다.
- V4: Focus Room. 구매한 꾸미기 소유권/배치와 성장 상태를 저장한다. 집중 도중에는 상점이나 보상 애니메이션을 노출하지 않는다.

## 배우면서 읽는 구조
프론트엔드는 브라우저에서 버튼과 화면을 담당한다. 백엔드는 요청을 검증하고 사용자의 데이터를 읽거나 변경한다. API는 두 영역 사이의 약속이다. DB는 서버를 껐다 켜도 남는 데이터 저장소다. 인증은 요청한 사람이 누구인지 확인하고, 인가는 그 사람이 해당 기록을 다룰 권한이 있는지 확인한다. 상태관리는 현재 화면과 타이머 정보를 일관되게 유지하는 방법이다.

예를 들어 '집중 시작'을 누르면 프론트엔드가 API에 taskId를 보낸다. 백엔드는 로그인한 사용자의 할 일인지 확인한 다음 세션을 DB에 생성하고 그 상태를 돌려준다. 프론트엔드는 응답을 받아 남은 시간을 그린다. 사용자 ID나 완료 시간을 브라우저의 주장만 믿고 저장하지 않는다.
